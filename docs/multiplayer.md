# Многопользовательский режим: проект

Это проект, а не готовая реализация. Он описывает, что нужно сделать и что требует решений владельца. Выбор владельца: серверная часть на **Firebase (бесплатный тариф)**, чат **свободный, но с модерацией**.

## Что хочет владелец

- Отдельный сайт на 3 языках (русский, английский, грузинский), дизайн пока простой.
- Вход через Google и Telegram, герой выбирается уже в личном кабинете.
- Острова новых игроков появляются рядом, игроки могут воевать, дружить, заключать альянсы, обмениваться ресурсами, строить мосты между островами.

## Ограничения (правила проекта и закон)

Игроки — подростки 12–17 лет, а входы Google и Telegram дают личные данные. Поэтому:

1. **Храним минимум.** Только придуманный ник, аватар из набора игры, героя, остров, ресурсы. Почту, настоящее имя, фото и телефон из Google и Telegram не сохраняем и не показываем другим игрокам (берём только внутренний идентификатор входа).
2. **Согласие родителей.** Для детей до 13 лет (в ряде стран до 16) нужно согласие родителей, а у детей до 13 лет часто нет собственного Google-аккаунта. До запуска нужно: возрастной вопрос при входе, понятное для подростка и родителя описание того, что хранится, кнопка «удалить мой аккаунт и данные».
3. **Чат с модерацией.** Свободный текст обязательно требует: фильтр слов, кнопка «пожаловаться», блокировка игрока, журнал жалоб и живой модератор (владелец или назначенный им взрослый). Без модератора чат включать нельзя. Первый шаг — чат только готовыми фразами и значками, свободный текст включить позже.
4. **Секреты.** Ключ бота Telegram и ключи сервисов нельзя хранить в коде на GitHub. Владелец создаёт проект Firebase и бота Telegram (через BotFather) сам и кладёт секреты в безопасное хранилище. ИИ-помощник не вводит ключи и пароли.

## Важная проблема: бесплатно ли это

- **Google-вход** в Firebase бесплатный (Authentication).
- **Telegram-вход** в Firebase «из коробки» не поддерживается. Нужен маленький серверный код, который проверяет подпись Telegram секретным ключом бота и выдаёт Firebase «пропуск» (custom token). Для этого в Firebase нужны Cloud Functions, которые требуют тариф Blaze (нужна банковская карта, есть бесплатная квота, но это уже платный сервис по правилам). Бесплатная замена: бесплатный Cloudflare Worker с тем же кодом (нужен ключ сервисного аккаунта Firebase в его секретах).
- **Решение владельцу:** допустимо ли подключение карты к Blaze (с лимитом расходов) или идём через Cloudflare Worker (без карты, но ещё одна платформа). Пока можно начать только с входа через Google и добавить Telegram позже.

## Архитектура (черновик)

- Сайт: статические страницы на том же GitHub Pages (`/site/…`) или отдельный адрес: лендинг, вход, личный кабинет (ник, аватар, выбор героя, друзья, альянс), кнопка «Играть».
- Firebase Authentication: Google (+ Telegram через custom token позже).
- Firestore:
  - `players/{uid}` — ник, аватар, герой, уровень, когда в сети;
  - `islands/{uid}` — положение острова в мире (сетка, новые острова рядом с последним), постройки, открытые мосты;
  - `friends`, `alliances`, `trades`, `bridges`, `reports`;
  - правила безопасности: каждый пишет только свои данные, обмен и мосты — через транзакции, чтобы нельзя было взять чужие ресурсы.
- Облачное сохранение игры вместо `localStorage` (то же JSON-сохранение, версия 8+).
- «Воевать»: сначала асинхронно (рейд на остров другого игрока по кнопке, бой с его защитой), потом по желанию живые бои на арене (для них нужен сервер реального времени: Firebase Realtime Database или отдельный сервер WebSocket).

## Порядок работы

1. Сайт-каркас на 3 языках, вход через Google, личный кабинет с выбором героя, облачное сохранение. Игра работает по-старому без входа (как гость).
2. Карта мира: острова игроков рядом, можно навестить чужой остров (только смотреть), друзья по коду.
3. Обмен ресурсами и мосты между островами (с проверками на сервере), альянсы.
4. Вход через Telegram.
5. Чат готовыми фразами, потом свободный чат с модерацией.
6. Нападения на чужие острова и живая арена.
